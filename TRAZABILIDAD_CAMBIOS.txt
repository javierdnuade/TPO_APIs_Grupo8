23-06 - Entrega 3 Parte 3 (Anulacion de creditos y cobranzas)
Backend - Reglas de anulacion y control de permisos
- Creditos: se agrego la anulacion logica para poder marcar creditos como anulados sin borrar informacion del sistema.
- Cobranzas: se agrego la anulacion logica para permitir revertir cobranzas del dia y mantener el historial de movimientos.
- Reglas de negocio: se incorporaron validaciones para evitar anular creditos que ya tengan cobranzas registradas y para permitir anular cobranzas solo si fueron hechas en el dia actual.
- Permisos: se reforzo la validacion para que solo los usuarios autorizados puedan realizar estas anulaciones.
- Mensajes del sistema: se mejoro la devolucion de errores para informar de forma clara por que una anulacion fue rechazada.

Frontend - Pantallas y seguimiento visual
- Creditos: se agrego el boton Anular en la pantalla de creditos, mostrandolo solo cuando el usuario tiene permiso y ocultandolo si el credito ya esta anulado.
- Cobranzas: se agrego el boton Anular en la pantalla de cobranzas, respetando permisos y el estado actual de cada registro.
- Visualizacion: los creditos y cobranzas anulados ahora se muestran diferenciados para que el usuario pueda identificarlos rapidamente.
- Integracion con mensajes: la interfaz ahora muestra el motivo exacto enviado por el backend cuando una anulacion no puede realizarse.
- Actualizacion en pantalla: se conectaron estas acciones al estado global para reflejar los cambios sin necesidad de recargar manualmente la pagina.

14-03
Backend - Dashboard de estadisticas (modulo general)

- Entidad Cuota: Se agrego el atributo pagada (boolean) para permitir el seguimiento del flujo de caja y estados de mora.
- CreditoRepository y CuotaRepository: Se desarrollaron consultas personalizadas con @Query (JPQL) para calculos de agregacion:

- Logica: Manejo de valores nulos y calculos de promedios para estabilidad ante bases de datos vacias.

Endpoints REST (controller)
- DashboardController: Endpoint GET /api/dashboard/stats.
- Respuesta: ResponseEntity con codigos HTTP adecuados y formato JSON.

Seguridad (JWT)
- SecurityConfig: Se actualizo el SecurityFilterChain para incluir la proteccion del modulo.
- Autorizacion: Solo usuarios con ROLE_ADMIN pueden acceder a los datos estadisticos.
- Validacion: Se valida la firma del token JWT mediante JwtAuthFilter antes de permitir el acceso.
